# GitHub 连接与学习档案约定

- 创建日期：2026-08-20
- 更新时间：2026-08-20
- 分类：学习管理
- 状态：已完成

## 原始问题

1. 是否可以连接 `NingWen2000/Reverse-Learning` 仓库？
2. 是否可以修改仓库，并把后续问题整理后上传？

## 当前结论

- 仓库已确认可访问，默认分支为 `main`。
- 后续 CTF Reverse 学习问题可以整理为 Markdown 笔记。
- 笔记以分析过程为核心，覆盖 Ghidra 静态分析、关键汇编、Windows 底层机制和 x64dbg 动态验证。
- 发布前检查敏感信息和比赛公开规则，避免上传 Flag、凭据或禁止公开的附件。

## 归档流程

1. 保留问题背景、样本环境和已知现象。
2. 先提出分析路径，再记录验证结果。
3. 分开整理静态证据与动态证据。
4. 将失败尝试和误判原因写入“易错点”。
5. 提炼可迁移的方法，并给出下一步练习。
6. 更新总索引后再提交到仓库。

## 写作风格

- 写成实际学习过程中会留下的工作笔记，不追求百科全书式的完整。
- 结构跟着问题走，不要求每篇都套用同一组标题。
- 优先保留具体地址、指令、断点、寄存器变化和判断依据。
- 暂时无法确认的地方直接标出来；失败的断点或错误判断有学习价值时也保留。
- 区分“准备验证”和“已经验证”，没有实际调试记录时不写成亲自跑过。
- 少用空泛总结、整齐对称的清单和固定结尾，让篇幅与问题本身匹配。

## 约定边界

- 默认归档本项目中的 CTF Reverse 学习内容。
- 与逆向学习无关或含私人信息的问题不自动公开。
- 比赛进行期间只保存本地分析；确认允许公开后再上传复盘。
- 远程发布前核对本次文件清单与改动内容。

## 后续动作

从下一次 Reverse 问题开始，使用仓库中的统一模板记录。复杂题目可以随着分析推进持续更新同一篇笔记，直到静态推断和动态验证相互印证。
